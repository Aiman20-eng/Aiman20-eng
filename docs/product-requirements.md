# وثيقة متطلبات المنتج — AI Context Builder

## 1. ملخص المنتج

**AI Context Builder** إضافة متصفح موجهة للمستخدم العربي تساعده على حفظ سياقات مشاريعه محلياً، ثم إدراج السياق المناسب داخل منصات الذكاء الاصطناعي مثل ChatGPT وClaude وGemini بنقرة واحدة.

يحل المنتج مشكلة تكرار شرح المشروع أو الخلفية أو التعليمات في كل محادثة جديدة مع أدوات الذكاء الاصطناعي، وذلك عبر بناء Prompt منظم من بيانات المشروع المحفوظة محلياً.

## 2. المشكلة

يعاني مستخدمو الذكاء الاصطناعي من المشكلات التالية:

- تكرار كتابة وصف المشروع والتقنيات والمتطلبات في كل محادثة.
- ضياع تفاصيل مهمة بين المحادثات المختلفة.
- اختلاف جودة الإجابات بسبب عدم ثبات السياق المقدم للنموذج.
- استهلاك وقت المستخدم في إعداد Prompt طويل قبل بدء العمل الحقيقي.
- قلق الخصوصية عند استخدام أدوات تحتاج خادماً أو مزامنة خارجية.

## 3. الرؤية

توفير أداة عربية، محلية، خفيفة وسريعة تجعل بناء وإدراج سياق المشروع عملية منظمة وقابلة لإعادة الاستخدام، مع الحفاظ الكامل على خصوصية بيانات المستخدم.

## 4. الأهداف

### أهداف الإصدار الأول

- إنشاء وإدارة عدد غير محدود من المشاريع.
- حفظ بيانات المشاريع محلياً باستخدام IndexedDB.
- توليد Prompt عربي منظم تلقائياً من بيانات المشروع.
- توفير قوالب جاهزة لمجالات تقنية وإبداعية شائعة.
- إدراج السياق داخل ChatGPT وClaude وGemini عبر زر داخل الصفحة.
- دعم البحث بين المشاريع.
- دعم الاستيراد والتصدير بصيغة JSON.
- تقديم واجهة عربية RTL احترافية بالوضع الفاتح افتراضياً.

### أهداف غير مطلوبة في الإصدار الأول

- لا يوجد Backend.
- لا توجد مزامنة سحابية.
- لا توجد حسابات مستخدمين.
- لا توجد AI APIs.
- لا توجد تحليلات خارجية أو تتبع للمستخدم.

## 5. الجمهور المستهدف

- المطورون العرب.
- مهندسو البرمجيات والمنتجات.
- صناع المحتوى.
- رواد الأعمال.
- مستخدمو ChatGPT وClaude وGemini.

## 6. شخصيات المستخدمين

### 6.1 مطور برمجيات

يريد حفظ تفاصيل مشروع Laravel أو React وإرسالها للذكاء الاصطناعي عند طلب مراجعة كود أو بناء ميزة.

### 6.2 صانع محتوى

يريد حفظ هوية العلامة، النبرة، الجمهور المستهدف، وأهداف المحتوى لاستخدامها في كتابة منشورات أو مقالات.

### 6.3 رائد أعمال

يريد حفظ وصف منتج SaaS، نموذج العمل، الشريحة المستهدفة، والمتطلبات لطلب أفكار تسويقية أو خطط تطوير.

## 7. نطاق الإصدار الأول

### 7.1 إدارة مساحات العمل

يستطيع المستخدم:

- إنشاء مشروع جديد.
- تعديل مشروع موجود.
- حذف مشروع بعد تأكيد واضح.
- عرض قائمة المشاريع.
- البحث حسب الاسم أو الوصف أو التقنيات.
- اختيار مشروع نشط لإدراجه داخل صفحات الذكاء الاصطناعي.

### 7.2 بيانات المشروع

لكل مشروع الحقول التالية:

- اسم المشروع.
- وصف المشروع.
- التقنيات المستخدمة.
- أهداف المشروع.
- المتطلبات.
- تعليمات خاصة للذكاء الاصطناعي.
- ملاحظات إضافية.
- القالب المستخدم إن وجد.
- تاريخ الإنشاء.
- تاريخ آخر تحديث.

### 7.3 بناء السياق

يقوم النظام بتوليد Prompt عربي منظم يحتوي على:

- مقدمة توضّح أن النص التالي هو سياق ثابت للمشروع.
- اسم المشروع.
- وصف المشروع.
- التقنيات المستخدمة.
- الأهداف.
- المتطلبات.
- تعليمات التعامل مع الإجابات.
- الملاحظات الإضافية.
- طلب صريح من نموذج الذكاء الاصطناعي بالالتزام بالسياق.

### 7.4 القوالب الجاهزة

القوالب الأولية:

- Laravel.
- Flutter.
- React.
- Node.js.
- SaaS Startup.
- Content Creation.

كل قالب يملأ حقولاً إرشادية قابلة للتعديل، ولا يفرض قيوداً على المستخدم.

### 7.5 الإدراج بنقرة واحدة

عند فتح منصة مدعومة، تضيف الإضافة زراً داخل الصفحة بعنوان:

> إدراج سياق المشروع

عند الضغط:

1. يفتح اختيار سريع للمشروع إن لم يكن هناك مشروع نشط.
2. يتم توليد السياق من بيانات المشروع.
3. يتم إدراج النص في مربع الكتابة الحالي.
4. يظهر تنبيه نجاح قصير داخل الصفحة.

### 7.6 الاستيراد والتصدير

- تصدير جميع المشاريع في ملف JSON.
- استيراد ملف JSON صحيح البنية.
- التحقق من البنية قبل الإدخال.
- منع فقدان البيانات عبر دمج البيانات المستوردة بدلاً من حذف البيانات الحالية.

## 9. المتطلبات غير الوظيفية

- الواجهة عربية بالكامل وباتجاه RTL.
- الوضع الفاتح هو التصميم الافتراضي.
- لا يتم إرسال أي بيانات خارج جهاز المستخدم.
- تحميل سريع داخل Popup وداخل صفحات الذكاء الاصطناعي.
- كود TypeScript صارم قدر الإمكان.
- مكونات React قابلة لإعادة الاستخدام.
- بنية Feature Based Architecture.
- عدم استخدام مكتبات غير ضرورية.
- إضافة تعليقات توضيحية للكود المهم فقط.
- دعم Chrome وEdge عبر Manifest V3.

## 10. الخصوصية والأمان

- جميع البيانات محفوظة محلياً في IndexedDB.
- لا توجد طلبات شبكة من الإضافة في الإصدار الأول.
- لا توجد مفاتيح API.
- لا توجد صلاحيات واسعة غير مبررة.
- صلاحيات المواقع تقتصر على منصات الذكاء الاصطناعي المدعومة.
- الاستيراد يتحقق من JSON قبل التخزين.

## 11. معايير القبول

- يستطيع المستخدم إنشاء مشروع وحفظه ثم رؤيته بعد إعادة فتح الإضافة.
- يستطيع المستخدم تعديل وحذف مشروع.
- يستطيع المستخدم البحث في المشاريع فورياً.
- يستطيع المستخدم توليد Prompt منظم باللغة العربية.
- يظهر زر الإدراج داخل ChatGPT وClaude وGemini.
- عند الضغط على زر الإدراج يتم إدخال النص داخل مربع الكتابة النشط.
- يستطيع المستخدم تصدير ملف JSON واستيراده بنجاح.
- لا يتم إجراء أي اتصال خارجي أثناء الاستخدام.
- جميع النصوص العربية تعرض باتجاه RTL دون كسر بصري.

## 12. مؤشرات النجاح

- تقليل وقت إعداد السياق قبل المحادثة.
- سهولة إعادة استخدام سياقات المشاريع.
- ثقة المستخدم بأن بياناته لا تغادر جهازه.
- واجهة مفهومة للمستخدم العربي دون الحاجة لتوثيق طويل.
